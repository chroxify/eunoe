# Planted-fact suite: held-out test split

2026-10-08. 24 sessions (90–120 turns each, 12 real repos), 25 planted facts
per session, 600 facts total. Final strategy frozen before this run
(`planted-frozen.md`): **rolling+both**, runner-up **trim+both**. Answering model
`claude-sonnet-5-5` in every arm; every arm sends the same canonical system
prompt and tools. Scored by exact match against the planted value, no judge.
Full tables: `bun bench/planted/report.ts --tag=test --split=test`.

## Pre-registered hypotheses for rolling+both (SPEC §6)

| | hypothesis | result | verdict |
|---|---|---|---|
| P1 | recalls more than native (lower bound > 0) | +28.3 [+16.5, +40.5] | **pass** |
| P2 | ≥ 90% overall | 99% | **pass** |
| P3 | ≥ 85% in every depth bucket and fact type | lowest 96% (superseded) | **pass** |
| P4 | tasks no worse than native (lower bound > −5) | −0.0 [−5.4, +5.4] | **fail**, by 0.4 points |
| P5 | stale rate ≤ native | 0% vs 1% (tasks), 0% vs 0% (recall) | **pass** |
| P6 | context at recall ≤ full | 118k vs 411k | **pass** |

P4 fails on the interval, not the estimate: rolling+both applies 92% of
instructions unprompted, exactly native's rate, but 24 sessions with ~3
implicit tasks each are too few to bound the difference within 5 points.
No arm, including full, reaches that bound (full's lower bound is −6.0).

## What this does and does not show

- **Shown:** on long sessions with facts placed where summaries skip them,
  Claude Code's own compaction loses about 30% of them (tool output, errors,
  decisions, superseded rules: 50–56%). rolling+both keeps 99%, at every depth
  from 1 to 61+ turns back, with a context 3.5× smaller than the full session
  and the fewest tokens processed of any arm.
- **Not shown:** that rolling+both remembers more than native+guide. Both
  reach 99%. The difference is cost: native+guide searches the transcript
  ~23 times per session and processes 2.7× the tokens; rolling+both brings
  the matching output back by itself (2.7 lookups, 40s vs 88s).
- **Not shown:** better instruction-following than native. Equal rates,
  interval too wide (P4).
- `full` (the whole session) is the ceiling at 100%, but needs ~411k tokens
  at the cut and is only possible on 1M-token models.

## Component revisions on the same test split (added 2026-10-08)

After the frozen run, the two components were tuned on dev only
(`SPEC.md` Part C) and each revision was run once on these 24
sessions, same answering model, same prompt, same scoring.

| arm | recall | worst bucket | tasks applied | context at recall | tokens / session | lookups | wall |
|---|---|---|---|---|---|---|---|
| rolling+both (frozen) | 99% | 96% | 92% | 118k | 490k | 2.7 | 40s |
| rolling+both2 (turn-budget evidence, 6-line recall windows, narrative indexed) | 99% | 98% | 92% | 110k | 304k | 0.1 | 40s |
| **rolling+both3** (both2 + Jev rerank over BM25's top 30) | **99%** | **99%** | **95%** | **110k** | **305k** | **0.1** | **39s** |

Paired against native: both3 recall +29.2 [+17.2, +41.5], tasks +3.6
[−1.2, +8.3], 12 sessions better / 0 worse. The tasks interval now clears
the P4 bound (−5) that the frozen arm missed by 0.4; the other five
hypotheses hold as before. both3 has 1 unknown and 3 wrong answers out of 600,
matches `full` on every fact type and depth, and processes 38% fewer tokens
than the frozen arm with no transcript lookups. The Jev call adds about
0.3 s per user message and no measurable tokens.

## Limits

One developer's repos; sessions generated by Opus from scripted outlines,
not recorded from real work; one answering model; single run per arm. The
generalisation check on the real-session suite's real sessions (SPEC §7) is below.

## Generalisation to real sessions (SPEC §7)

rolling+both and native, plus native+guide, on the real-session suite's 27 points (19 real
sessions, 8 synthetic), 318 vetted questions, Sonnet answering, Opus and
Sonnet judging. Every arm used the same pinned system prompt per point. Full
table: `results/real-sessions.md`.

| arm | recall | real only | tool output | decisions | recent (1–3 turns) | 26+ turns ago | vs native (95% CI) · points better / worse |
|---|---|---|---|---|---|---|---|
| native | 60% | 60% | 37% | 55% | 33% | 56% | – |
| native+guide | 89% | 92% | 89% | 79% | 88% | 93% | +28.8 [+20.9, +36.9] · 26 / 0 |
| **rolling+both** | **89%** | **90%** | 76% | **91%** | **94%** | 89% | **+29.3 [+21.3, +37.0] · 23 / 4** |

**Verdict: generalises.** rolling+both beats native on real sessions by the
same margin as on the planted suite (+29 vs +28), and the interval excludes
zero. As on the planted suite, it ties native+guide overall rather than
beating it: it is stronger on decisions and recent turns, weaker on answers
that only appeared in tool output (76% vs 89%).

Recall on real sessions is lower for every arm than on planted facts (89% vs
99%) because the real-session suite's questions are judged free text written by an LLM, not
exact planted values.

Native here (60%) is lower than in the earlier the real-session suite pass (89% on 7 points):
that pass answered with Opus and had native on a shorter system prompt than
the other arms. This run answers with Sonnet and pins the same prompt for
every arm.
